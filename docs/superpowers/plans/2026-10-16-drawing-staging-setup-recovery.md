## Review Focus

1. A valid encrypted envelope from an untrusted run must not establish provenance: test matching decryption with wrong repository/run/artifact identity and require refusal.
2. Cancellation after remote creation but before durable readback must never produce a second create: inject loss at each write boundary and assert zero subsequent writes/retries.
3. A changed membership/creator or unknown child between setup stages must prevent further mutations: change exact observer readback and assert the request was not sent.
4. A wrong caller API key or leaked setup key in an app request must fail before transport: exercise both headers and scrubbed child environments with matching positive controls.
5. A local reparse point or inherited broad ACL must not expose recovery material: execute Windows-owned temporary-directory negatives and assert no plaintext/private-key file exists afterward.

## Interfaces shared by the tasks

Define these types in `e2e/drawing-cutover-setup.ts`, separately from `FixtureManifest`; leave existing acceptance contracts unchanged.

- `SetupContext`: version `1`, fixed stage ref, full candidate SHA, UUID run ID, decimal-string workflow run/attempt IDs, phase `setup-bootstrap | setup-complete`, nonnegative checkpoint sequence, lowercase SHA-256 recipient fingerprint.
- `SetupPlan`: context binding, ISO `createdAt`/`expiresAt`; exact seven-alias address roster; two distinct reviewed organization name/slug pairs; four distinct project name/number pairs bound to A1/A2/B1/B2; reviewed public-key and setup-key digests/identifier/owner attestation; prerequisite-evidence digests. No arbitrary routes/SQL/permission lists. Require `createdAt <= now < expiresAt <= createdAt + 24 hours`.
- `FoundationReceipt`: context/plan digest, status `AWAITING_ENTITLEMENT_REVIEW | FOUNDATION_PREPARED | STOPPED | UNKNOWN_COMMIT_STATE`, monotonic operation intents/results, exact observed actor/org/project/membership IDs and creator/role bindings. `STOPPED` means a known rejection/known partial result, not an ambiguous commit. Credentials are held separately in `PrivateRecoveryPayload`; no receipt or status establishes acceptance.
- `PrivateRecoveryPayload`: strict plan, receipt, seven generated credentials and optional exact MFA factor/secret. Exclude broad API keys, deployment PATs and private encryption keys. `SetupResume` also binds independently reviewed receipt/artifact/source identity and exact post-entitlement readback; it is never a `FixtureManifest`.
- `RecoveryEnvelope`: fixed version/algorithm, strict context, base64 wrapped key/nonce/tag/ciphertext; canonical context is AAD. Reject unknown fields, noncanonical encoding, wrong lengths and inputs exceeding the bounded plaintext plus fixed RSA/header/base64 overhead.

Campaign `runId` and candidate SHA remain constant across bootstrap/complete, but execution run/attempt/phase contexts differ. Decrypt bootstrap using its independently pinned original context; never relabel it as complete. Complete's new reviewed plan/digest binds that prior receipt and current execution. An expired plan needs fresh review/live readback, not account recreation. `ArtifactBinding` keeps immutable artifact ID, repository/run/attempt/source, **archive SHA-256** and **ciphertext-file SHA-256** distinct; the upload action's archive digest is not the ciphertext digest.
