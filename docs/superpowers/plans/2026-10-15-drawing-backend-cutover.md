# Drawing Backend Cutover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make reviewed drawing intake/revision atomic, recoverable and protected against application/API bypass; prove it in staging and deliver the exact production approval package without applying production changes.

**Architecture:** Extend the uninstalled one-set transaction with atomic New Set intake, shared private receipts and adopted-source retention. Typed adapters and an identity-scoped durable journal replace split client writes; database privileges and audited command entrypoints enforce the boundary. A versioned export extension preserves source observations without creating restore, retry or approval authority.

## Review Focus

1. Same filename uploaded twice with a late 409: never adopt someone else's bytes based on a duplicate response alone; Task 7 pins this.
2. One browser tab replaces its draft while an older response arrives: it must not erase/replay the newer operation; Task 6 pins this.
3. A new revision retains callouts, hyperlinks or a stale titleblock label from the old PDF: unavailable/changed-page derivations must clear, not migrate; Tasks 2, 8 and 9 pin this.
4. A hold is released after a different revision became current: it must not restore a prior release status onto the replacement PDF; Task 4 pins this.
5. Evidence is added or erased while a multi-page export runs: either export one stable observation roster or explicitly fail/restart, never return silently incomplete success; Task 11 pins this.

Review inputs are readonly versions of their corresponding exact request types; builders validate and clone, not silently fill absent fields.
