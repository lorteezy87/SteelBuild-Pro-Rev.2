## New Deficiencies Found

### CRITICAL

#### C-01 — Anthropic API Key Exposed in Client Bundle
**Severity:** CRITICAL  
**File:** `src/api/supabaseClient.js:583`  
**Rule:** Secret keys must never exist in client-side code.

**What's happening:** The LLM fallback (Tier 2) reads `import.meta.env.VITE_ANTHROPIC_API_KEY` and forwards it as `x-api-key` to `api.anthropic.com` directly from the browser. Vite inlines every `VITE_*` variable into the bundled JavaScript at build time — there is no runtime secret store. The key is visible in plain text in DevTools → Sources and in any downloaded bundle.

**Evidence:**
```js
// src/api/supabaseClient.js ~line 583
const apiKey = import.meta.env.VITE_ANTHROPIC_API_KEY;
// ...
headers: {
  'x-api-key': apiKey,
  'anthropic-version': '2023-06-01',
  'content-type': 'application/json',
}
```

**Impact:** An attacker can extract the key and incur unbounded Anthropic API charges, or use it to access Anthropic's API under SHS Steel's account for arbitrary prompts.

**Fix required (in order):**
1. Create `supabase/functions/llm-proxy/index.ts` — hold the Anthropic key in a Supabase secret (`supabase secrets set ANTHROPIC_API_KEY=…`).
2. Deploy the function (`supabase functions deploy llm-proxy`).
3. Remove `VITE_ANTHROPIC_API_KEY` from `.env.local` (and from any CI secrets / Vercel env vars if deployed).
4. Delete the Tier-2 direct-API path from `InvokeLLM` — once the Edge Function is live, Tier 1 succeeds and Tier 2 is never reached.

**Risk if not fixed:** HIGH — active credential exposure in production.

#### H-02 — Missing Migration File for `schedule_impact_days`
**Severity:** HIGH  
**Rule:** Every schema change must exist as a numbered SQL file in `supabase/migrations/`.

**What's happening:** The `change_orders.schedule_impact_days` column was applied to the live Supabase project via MCP tooling during the remediation session. However, only four migration files exist on disk:
- `001_initial_schema.sql`
- `002_storage.sql`
- `003_rls_policy_intent.sql`
- `004_storage_private.sql`

No `005_*.sql` exists. Any fresh `supabase db push` from this repo will not include the column, causing `COFormModal.jsx` to throw `[change_orders.create] Could not find the 'schedule_impact_days' column` on any dev machine or CI environment.

**Fix required:** Create `supabase/migrations/005_change_orders_schedule_impact.sql`:
```sql
-- Add schedule_impact_days to change_orders
-- Applied live 2026-04-20; committed here for reproducibility
ALTER TABLE change_orders
  ADD COLUMN IF NOT EXISTS schedule_impact_days INTEGER DEFAULT 0;
```

#### M-02 — Inline `borderRadius: {number}` in 235 Files
**Severity:** MEDIUM  
**Rule:** Border-radius must use CSS variable tokens, not raw numbers.  
**Token reference:** `--radius-card: 10px`, `--radius-btn: 8px`, `--radius-input: 8px`, `--radius-badge: 6px`.

**Note on the "2px rule":** The architectural rule references 2px border-radius as a standard. However, the current token file defines 6–10px radii. The token file takes precedence as the implemented source of truth. The rule should either be updated to reflect the token values, or the tokens should be updated. This must be clarified before the sweep begins.

**Fix required:**
1. Clarify/align the radius rule with the token values.
2. Replace `style={{ borderRadius: N }}` with `style={{ borderRadius: 'var(--radius-btn)' }}` (or appropriate token).
3. For Recharts charts that accept numeric props, compute the value from a CSS variable via `getComputedStyle` or hardcode to the token value.

**Priority start:** `src/components/shared/PhoenixModal.jsx` — uses `borderRadius: 8` and `borderRadius: 16`; it is a shared primitive touched by many features.

#### M-04 — Inconsistent React Query Key Naming (234 call sites, 88 files)
**Severity:** MEDIUM  
**Impact:** Components fetching the "same" data with different query keys get independent network calls. Mutations invalidating `['projects', id]` do not refresh components that subscribed to `['project', id]`. This causes silent stale-data bugs that are difficult to reproduce.

**Sample key collisions confirmed:**

| Pattern A | Pattern B | Same data? |
|---|---|---|
| `['projects', activeProject?.id]` | `['project', projectId]` | Yes |
| `['drawings', projectId, filters]` | `['drawings', activeProject?.id]` | Yes (same project) |
| `['deliveries']` | `['deliveries', projectId]` | Yes (same project scope) |
| `['change_orders', projectId]` | `['changeOrders', projectId]` | Yes (camelCase vs snake_case mismatch) |

**Fix required:** Create `src/lib/queryKeys.js` with a factory pattern:
```js
export const queryKeys = {
  projects: () => ['projects'],
  project: (id) => ['projects', id],
  drawings: (projectId, filters) => ['drawings', projectId, filters],
  deliveries: (projectId) => ['deliveries', projectId],
  changeOrders: (projectId) => ['change_orders', projectId],
  // ...
};
```
Import and use consistently. Enforce via code-review checklist.

#### M-05 — `app-params.js` Uses Empty-String Fallback for Supabase URL
**Severity:** MEDIUM  
**File:** `src/lib/app-params.js:11`

```js
appId: import.meta.env.VITE_SUPABASE_URL || '',
```

`lib/supabase.js` now throws a hard error on missing `VITE_SUPABASE_URL` (good). But `app-params.js` silently falls back to `''`. Code that reads `appParams.appId` receives an empty string and fails silently — exactly the antipattern that was removed from `supabase.js`.

**Fix required:** Either throw (`if (!url) throw new Error('VITE_SUPABASE_URL missing')`) or remove `appParams.appId` entirely since `supabase.js` is the single source of truth for the Supabase URL.

#### L-03 — Font Token Mismatch vs Architectural Rule
**File:** `src/styles/tokens.css:137-140`

```css
--font-display: 'Barlow Condensed', 'Inter', sans-serif;
--font-body:    'Inter', 'Barlow', sans-serif;
```

**Architectural rule states:** Headings use Space Grotesk; numbers use IBM Plex Mono.  
**Token file states:** Display uses Barlow Condensed; body uses Inter.

IBM Plex Mono is correctly tokenized as `--font-mono`. Space Grotesk is absent from the token file.

**Fix required:** Either add `--font-heading: 'Space Grotesk', sans-serif` and use it for heading elements, or update the architectural rule to reflect that Barlow Condensed is the deliberate heading choice. Pick one source of truth.
