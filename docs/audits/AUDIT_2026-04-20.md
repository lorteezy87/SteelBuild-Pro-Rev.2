## 1. Executive Summary

The codebase is in good structural shape: 44 clean sequential Supabase migrations, a robust CSS token system (196+ custom properties), a solid base44→Supabase shim covering 37 entities, and a successful multi-session refactoring effort that has reduced five major pages (Financials, ResourceScheduling, RFIs, Constraints, Reports, WorkPackages) from ~1500–1800-line monoliths into feature folders.

However, this audit surfaces **24 deficiencies** across four severity bands. The most impactful cluster is a **data-layer cache-correctness bug** (scoped vs. unscoped `queryKey` mismatches) that causes mutations to appear successful while the UI continues to show stale data in at least four confirmed sites (Layout, ActionItems, FabRelease, ResourceScheduling).

The hard architectural rules are violated at scale: 15 `<form>` tags, 10 files importing Radix `Dialog`, 140 files with hardcoded hex colors, and 80+ files with non-standard hardcoded `borderRadius`. The CSS token system exists and is mature, but component-level adoption has drifted.

Two expected modules — **Submittals** and **PMA** — don't exist as standalone surfaces. Submittals are tracked as document metadata only; "PMA" is absent from the codebase entirely.

Phase 2 (remediation) should begin with the data-layer fixes (D01, D06, D05) since they affect data correctness, followed by systemic design-system cleanup (D04, D09), then carve-ups and UX gaps.

### 🔴 Critical

> **POST-AUDIT CORRECTION (2026-04-20 later same day):** D01 has been downgraded to **not-a-bug** after verification. The audit agent's finding misread React Query v5 semantics. `invalidateQueries({ queryKey: ["X"] })` defaults to `exact: false` and **does** prefix-match `["X", projectId]`, and no `exact: true` flag overrides this anywhere in the codebase. The reported "orphan" keys (`["wps-all"]`, `["action-items-all"]`) are legitimate cross-page invalidation targets — `ProductionNotes.jsx:66` queries `["wps-all"]`; `Dashboard.jsx:25` and `Reports.jsx:73` query `["action-items-all"]`. The naming chaos remains a real problem (tracked under D06), but no data-correctness bug exists here.

## 5. Proposed Fix Order

Rationale: fix data-correctness first (user trust, silent bugs), then design-system compliance (visible gloss + consistency), then carve-ups (maintainability), then deps & hygiene.

1. **D01** — fix the four confirmed stale-cache sites. Ship migration first if any needs a schema adjustment. *(Critical, user-facing bug.)*
2. **D06 + D05** — introduce `src/services/queryKeys.js` registry, migrate the top 5 most-queried entities (WorkPackages, ChangeOrders, Deliveries, RFIs, Drawings) to use it, swap pages to `crudFeedback` helpers. Kills the mutation-consistency class of bugs at the root.
3. **D02** — replace 10 Radix `Dialog` imports with the fixed-overlay pattern. Verify DeleteDialog intent with user (if AlertDialog is allowed, leave; if not, swap).
4. **D03** — remove 15 `<form>` tags, convert onSubmit → onClick.
5. **D14** — small, high-leverage: Schedule imports canonical `PHASES`. (Eliminates a drift class.)
6. **D07 + D08** — add `LoadingSkeleton` + empty states to the 5+6 pages flagged.
7. **D13** — Expenses bulk-mutation success toasts.
8. **D04** — hex-to-token migration, top-15 offenders first (biggest ROI). Extend `tokens.css` to cover file-types + chart palette; drive a focused PR per-file group.
9. **D10** — 6 orange-decorative fixes.
10. **D22** — `dmsConstants.js` tokens.
11. **D20** — three font-family swaps.
12. **D09** — border-radius strategy decision. Pause for user direction: migrate to tokens, or redefine tokens at 2px and sweep, or relax rule? **Requires user input.**
13. **D15–D19** — carve-ups in order of biggest first (Deliveries → Expenses → Documents → Schedule → ResourceScheduling remainder). One commit per page.
14. **D24** — Layout.jsx defensive column checks: migration or code removal.
15. **D23** — console.log cleanup sweep.
16. **D21** — remove `moment`, `react-hot-toast`, stale `use-toast.jsx`. **Deletion — requires explicit user approval.**
17. **D11 + D12** — Submittals + PMA: **requires user input** on whether to build, scope, or close.
