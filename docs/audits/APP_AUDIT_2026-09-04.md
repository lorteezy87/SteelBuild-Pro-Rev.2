# App audit — 2026-09-04

Scope: high-traffic pages and the data routed to / from them, every KPI card,
the Drawings + Submittals modules, and the 3D model viewer with its piece
tracking. Ground truth for every status/column finding was the DB CHECK
constraints in `supabase/migrations/20260101000010_baseline_schema.sql` (plus
later migrations) and `src/types/supabase.ts`.

Legend: **Fixed** = shipped in this PR with tests. **Deferred** = verified but
left alone on purpose (reason given). Line numbers are as of `main@507bab4`.

---

## 1. 3D model viewer (Detailing Control Center → 3D Model)

### Fixed
- **Orbit drag cleared the selection.** OrbitControls' mouseup fires a
  synthetic click; the viewer now ignores clicks that travelled > 5 px.
- **"Set fab status" panel was dead.** Seven status buttons + a piece/assembly
  scope toggle rendered, but every click toasted an error unless the lot was
  canonical *and* exactly at fabricated→ship or delivered→erect. Replaced by a
  **Piece Control** panel driven by the same eligibility rules as the Piece
  Register (`logisticsDisabledReason`): shows the linked lot's lifecycle / hold
  / lot code, offers Ship / Deliver / Erect only when every selected lot is
  eligible (tooltip says why not), and deep-links to the register
  (`/PieceRegister?piece=<id>`).
- **Fab legend disagreed with the paint.** Canonical lifecycle used one palette
  (`CANONICAL_PIECE_COLORS`), legacy `fab_status` another (`FAB_STATUS_META`),
  and On Hold (red) was painted but never listed. One palette now; legend
  rows carry live counts and click-to-isolate.
- **No way to find a piece.** Added Find mark (exact → prefix → contains,
  natural sort), hover mark labels, Alt-click for the whole mark, Isolate /
  Hide / Show all, a Level cut slider (horizontal clipping plane), and
  keyboard shortcuts (F / I / H / U / Esc).
- **Saved-model fetch ignored HTTP errors.** A 403 on the signed URL was fed
  to web-ifc and surfaced as a parse error. Now checks `res.ok`.
- **Canonical join capped at 1000 lots.** The `pieces` query behind Fab colors
  is paged (`fetchAllProjectRowsPaged`).
- Removing a model / saving a model now invalidates the full Piece Control key set.

- **IFC "Save to project" never reached the server** (2026-09-05, user
  report). Three causes, all on the save path:
  1. `extractIfcRoster` read marks with web-ifc `getPropertySets(elementID)`,
     which does an inverse scan of every `IfcRelDefinesByProperties` line per
     element — O(parts × rels). On the 26k-part job that is minutes of blocked
     main thread and a Safari tab kill, so no request, no toast, no Sentry
     event. Now one pass over the relationships (part expressID → marks),
     yielding every 500 lines with "indexing properties N / M" progress.
  2. It re-parsed the whole IFC while the viewer's copy was still open
     (peak wasm memory ×2). The extractor now borrows the viewer's open model
     (`loadIfcGeometry().handle`, `viewerRef.getModelHandle()`) and fails
     loudly if that model is closed mid-read instead of returning a short
     roster.
  3. `importIfcRoster` superseded the prior model and soft-deleted its roster
     BEFORE inserting the new one, so one failed save left the project with
     only `superseded` registry rows (observed on project 3793bea9…). It now
     inserts the new registry row + roster first, discards them on failure,
     and only then retires the old model (`superseded_by` is set).
  Also: duplicate GlobalIds are deduped before insert (unique
  `model_elements(model_id, element_guid)`), the gzipped upload is checked
  against the 50 MB `app-files` object limit before it is sent, and the error
  toast names the step (read / compress / upload / register). Pure helpers in
  `src/lib/ifc/persistSteps.ts`.

### Deferred
- **Draw-call count.** One mesh per placed geometry (~10k on big Tekla
  exports). Merging into a single BufferGeometry with vertex colors and
  index-range picking would roughly halve frame cost; it changes the recolor /
  pick contract and needs a real IFC fixture to validate. Tracked as follow-up.
- **Exception releases are invisible in 3D.** A work package released with
  `is_exception = true` paints its lots "Released" like any other. Surface the
  flag in the Piece Control panel once `fab_releases` is joined into the tab.

## 2. Piece tracking (Piece Register / Piece Control)

### Fixed
- **Silent 1000-row caps** on `pieces` / `piece_station_completions` reads:
  Overview snapshot (`canonicalDashboardRepository`), station board
  completions (`productionRepository`), logistics board, shipping-list import,
  EPM→fab bridge, 3D canonical join. All go through the new
  `src/lib/pieceControl/pagedSelect.ts`. Offset paging in `repository.ts`,
  `relationshipsRepository.ts` and `modelElementLink.ts` now has a stable
  `.order("id")` (unordered offset paging can duplicate / skip rows).
- **Archive left the 3D projection live** (`trg_pieces_projection_after_change`
  did not fire on `is_deleted` / `deleted_at`). Migration
  `20260904120000_piece_archive_projection_sync.sql` detaches
  `model_elements` on archive, re-links on un-archive, refreshes WP progress,
  and repairs existing rows. Applied to project `kjrwqagyeswwoxpjkcko` on 2026-09-04.
- **Stale WP % after station advance / ship.** `invalidatePieceControlQueries`
  now pushes the work-package keys on `production` / `logistics` scopes; the
  register's hand-rolled `invalidate()`, Package Board and Relationship
  Manager use the shared `"all"` scope.
- **Weighted progress mixed pounds with piece counts.**
  `calculateWeightedProductionProgress` weights by pounds only when every
  actionable piece has a weight, else by quantity.
- **Bulk station advance** now skips `deleted_at` rows and split parents with
  live children (the server batch rejects those atomically).
- Register search covers lot code / sequence / area / external ref; row
  sub-label reads `is_container`; merged CSV import rows recompute
  `weight_each_lbs` so `pieceTons()` stops inflating tonnage.
- Piece Register subscribes to canonical realtime;
  `piece_station_completions` added to the realtime table list.

- **EPM → pieces write-through** (2026-09-05). The bridge used to UPDATE
  `pieces.lifecycle_status` from the browser, which the table grants reject
  (42501) and which skipped station completions / piece_events. New RPC
  `sync_production_stages_to_pieces` (migration `20260905090000`) walks each
  unique leaf lot through `advance_piece_station_impl` up to the target
  station and ships via `ship_piece_lots_impl`, per-lot tolerant (not
  released / on hold / ambiguous mark are reported, not fatal). Stage mapping
  in `src/lib/production/productionStageStations.ts`: Cut→cut, Fit→fit,
  Weld→weld, **Clean→qc** (positional), **Paint→ready_to_ship** (EPM has no
  ready-to-ship stage, so Paint = fabricated, matching the legacy colour),
  Shipped→ready_to_ship + ship. Backward EPM stages never regress canonical
  lots. Import and bulk-stage toasts now report advanced / unchanged / skipped.
  Applied to project `kjrwqagyeswwoxpjkcko` on 2026-09-05.

- **Imports tab "Assign + link from import" said nothing happened**
  (2026-09-05, user report). Applying a batch with a package selected already
  assigns every piece, so a later click finds all of them `unchanged` and the
  RPC returns `assigned: 0`; the toast translated that into "No work package or
  drawing sheet hints found". Verified on the 204-row BIMC FabSuite batch: all
  204 pieces were in WP-014 the whole time. The toast now reads the RPC's
  `unchanged` count ("204 already in WP-014") and says plainly when the source
  carries no sheet hints (FabSuite XML never does), and the applied panel shows
  where the batch's pieces sit in the live register. Helpers + tests in
  `src/lib/pieceControl/importAssign.ts`.

### Deferred (verified, not changed)
- `release_work_package_canonical_impl` computes release tonnage as
  `coalesce(weight_total_lbs, each*qty)` while `pieceTons()` prefers
  `each*qty`; `fab_releases.weight_tons` can disagree with the register.
- Gate CTEs filter `deleted_at IS NULL` only (not `is_deleted`). Latent today
  because `archive_piece_lots` writes both.
- Plain-CSV import path does not aggregate duplicate marks (PowerFab/IFC
  paths do). Behavior change for users; left as-is.
- "Exceptions" KPI sums rows + quantities + rows. Label/unit cleanup.

## 3. KPI cards and high-traffic pages

### Fixed
See commit `fix(kpi): correct status vocabularies, dates and routing on
high-traffic pages`. Highlights:
- Command Center "Approvals Pending" was permanently 0 (compared submittal
  status to drawing stages); "Open Action Items" dropped Draft/Submitted
  submittals; submittal overdue badges read a non-existent `due_date`.
- Field Hub counted `Completed` safety incidents as open and hid overdue
  inspections.
- Open / overdue RFIs counted `Void` on Dashboard, Projects, RFI strip,
  sidebar badge and Executive View; four different overdue definitions
  collapsed to one date-only rule.
- `enums.ts` RFI / Change Request vocabularies contradicted the DB.
- Dashboard "Drawings Need Attention" read a column that doesn't exist.
- Portfolio derive read `projects.status` (doesn't exist).
- Deliveries KPIs counted procurement rows and treated `Received` as open.
- Executive View truncated at 2000 rows (`list()` vs `listAll()`).
- Routing: legacy project redirect used `?id=` (page reads `recordId`);
  Reports empty state linked to a non-existent page; Portfolio Hub's tab
  strip never rendered on the default tab so Executive View was unreachable.

### Deferred
- Three "Portfolio Value" tiles (Portfolio, Projects, Executive) use three
  definitions (revised vs original contract, on-hold in/out). Pick one.
- "At Risk projects": computed health (Portfolio/Projects) vs stored
  `health_status` (Executive, Job Status Report).
- Resources "Utilization" is capped at 100% while "Over-Allocated" is non-zero.
- Two "Critical" RFI tiles mean different things (priority vs 30+ days late).
- `["projects"]` query key is shared by capped `list()` and uncapped
  `listAll()` fetchers; whichever mounts first wins.
- `src/lib/projectHealth.ts:167` also reads `project.status`.
- FieldHub renders gated module pages as tabs without `ModuleGate`.
- Dashboard "Reports" tile links into a module gated off by default.

## 4. Drawings and submittals

### Fixed
- **Revision upload wrote `issue_date` / `issued_by` onto `drawings`** — neither
  column exists, so every added/revised sheet threw PGRST204 inside a
  per-sheet `catch` and was counted as "failed". Removed from the drawings
  payload (kept on `drawing_sets`). Existing sheets are now located by
  `drawing_set_id` first (legacy name-only rows as fallback), and the
  "post-IFC revisions must be numeric" rule derives the set stage from its
  sheets instead of a non-existent `drawing_sets.stage`.
- **Letter revisions sorted / rolled up as 0.** `maxRev` and the REV column
  sort now use a natural compare (letters before numbers, numeric-aware).
- **Drawing overdue flipped at noon** (date-only shim). `isOverdue` /
  `daysLate` compare local calendar days.
- **Latest submittal per set depended on query order.** `buildSubmittalsBySetId`
  sorts by `submitted_date` desc itself.
- **Dead "Rejected / R&R / Returned" stage checks** in the hub rollup, process
  board and visual board (the stage CHECK never allows them). Replaced by
  `sheetNeedsAction()` = `set_approval_status === 'rejected'`; the test that
  asserted an impossible row was corrected.
- **Fab Release analytics** read a non-existent `drawings.status` and treated
  bare `set_approval_status` as released; now `stage` / `ifc_status` ∈
  {IFC, Released} only, matching `drawingReleaseReady.ts`.
- **Sheet response grid** snapshotted rows before responses loaded (saving
  duplicated rows) and never wrote `drawing_set_id`. Rows re-sync; payload
  carries the set id.
- **"+ New Round"** from Approved / Approved as Noted / Released / Void hit the
  DB transition trigger with a raw error; hidden in the UI and pre-validated
  in the mutation. `addSubmittalRound` now rolls the round back on *any*
  update failure, not only fab-release blocks.
- **`returned_date` never refreshed after round 1**, so risk aging measured
  from a months-old date and minted Critical action items. Set whenever the
  status transitions into a verdict status. `daysBetween` converts
  timestamps to the local day before slicing.
- **Navigation:** "back to set" sent `?set=` which Drawings ignored — now
  honored (pre-filter + pill); blocked-stage toasts opened a *create new
  submittal* form even though the block reason was an existing open
  submittal — now deep-link to it; `?revisionId=` switches to the owning
  sheet instead of erroring; ball-in-court now survives the drawing→submittal
  hand-off so IFC/OFS/BFA no longer collapse to BFA.
- **Export Fab Release modal** grouped name-only sheets separately from their
  FK siblings (gate could miss rejected sheets) and wiped a typed override on
  every evidence refresh.
- **Carry-forward zones** were matched to their clones by array position after
  a bulk insert; now matched on `parent_zone_id` and fail loudly on mismatch.
- Approval matrix no longer counts Void submittals as pending; the "final
  stage" message names Released, not IFC.

### Deferred
- `isClosedDrawing` (hub "Sets Released" KPI) still treats a bare
  `set_approval_status = approved` as released while the fab-release gate
  does not. Aligning it changes hub numbers; decide which definition wins.
- `computeStats` (legacy, name-grouped) and `computeStatsFromSubmittals`
  both exported and live.
- Four `useQuery`s share `["submittals", projectId]` with different sort
  orders; first mount wins.
- `?revisionId=` can switch to the owning sheet but not select a non-current
  revision (`useZoneData.ensureCurrentRevision`).
- The "Superseded Drawings Still Active" alert copy says IFC but the filter
  checks Released.

## 5. Test-suite note
`src/__tests__/components/DrawingSubmittalHub.test.jsx › embeds the Submittal
Register…` failed when run together with its directory siblings and passed in
isolation — reproduced identically on `main@507bab4`. Root cause: the lazy
Submittal Register chunk can take longer than the 1 s `findBy*` default on a
loaded worker. The wait is now 8 s; the directory passes back-to-back.

## 6. Database drift (2026-09-05)
A user hit "This feature needs a pending database update
(`list_drawing_impact_assignees`)" on drawing-impact assignment. Production
(`kjrwqagyeswwoxpjkcko`) was missing seven repo migrations. The
`supabase_migrations` table is not a reliable record here because migrations
are applied by hand in the SQL editor, so this was established by probing each
migration's objects (functions, triggers, columns, indexes) directly.

Missing until 2026-09-05: `20260801120000` (piece-mark relink),
`20260810053816` (drawing-impact assignees + assignee trigger),
`20260819001000` (org member default project role), `20260819002000`
(operational alerts engine), `20260819003000` (project workflow templates),
`20260825140000` (submittal approver notes).

**Hazard this exposed:** `20260904120000` (applied 2026-09-04) installed a
`pieces_projection_after_change` body that calls
`link_unlinked_model_elements_for_piece` from `20260801120000`, which had never
been applied. Every piece INSERT with a mark, every un-archive and every mark
change would have failed with "function does not exist". No such failure had
been logged yet. The catch-up bundle applied the six migrations in order and
then re-applied `20260904120000` so the archive-aware trigger body is the one
that stays. All objects verified present afterwards.

Process note: the "Supabase drift check (opt-in)" CI job would have caught
this; it is skipped on every PR today. Worth enabling.
